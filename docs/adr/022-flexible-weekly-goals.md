# ADR-022: Flexible weekly goals

Status: accepted for task 023, owner authorized implementation on 2026-10-15.

Add an optional weekly policy `{ target: 1..7, weekStartsOn: 0|1 }` to the existing effective schedule JSON. Weekly active versions use all seven weekdays; internal archived pauses use an empty set, retain their weekly policy and save resumeDays for the planned active weekdays. Preserve pending effective versions while archiving/restoring rather than activating a future goal early. Legacy versions remain unchanged. No dependency, permission, destructive schema or backend change. Migration v9 advances only user_version with SELECT 1, preserving every existing JSON byte and table; the existing newer-database guard prevents older v8 binaries interpreting weekly goals as daily schedules. No destructive schema change; backup v4 carries weekly policies and notes, while v1–v3 remain importable. Reject weekly fields in older backup versions rather than silently dropping them. Older apps must reject v4 rather than import it as daily schedules.

Snapshot the calendar week-start preference when creating/converting a weekly habit. Display preferences never change its saved week boundaries. A weekly policy retains that boundary across target edits, archive and restore. Switching between daily and weekly modes, or changing a weekly target, takes effect at the next boundary of the current/planned weekly policy. Repeated edits replace the same pending policy. Ordinary weekday/tolerance edits still start tomorrow. Renaming and appearance changes remain immediate. Converting to weekly does not reinterpret any earlier day.

Every eligible local date permits at most one binary win, including dates after the weekly target is reached. Extra wins remain visible in tiles and total wins; they do not create extra weekly achievements. Unfinished weekly dates are neutral flexible opportunities, not daily misses or tolerated completions. All Today rows retain exactly 14 dates. Weekly targets do not require a win every day and are excluded from the daily planned banner/all-day celebration; each actual weekly check-in still receives individual feedback. Weekly-only Today shows week-oriented encouragement.

For each fixed calendar week, count active weekly dates and real wins. The effective target is `min(configured target, active dates in that week)`. Thus a 3-day goal created Saturday with Monday boundaries needs 2 wins that short week; a normal week needs 3. Show the short-week adjustment explicitly. New archive pauses start tomorrow and restoration resumes tomorrow, preserving existing archive behavior. Full paused weeks are ignored; partially active weeks use the same target cap. No synthetic wins or backfilled grace dates are written.

Weekly streaks count consecutive achieved active weeks. An open week can extend the sequence immediately when its target is met; otherwise it stays pending until its final calendar day ends. A failed closed week breaks the sequence. Fully paused weeks are skipped. A change of schedule kind or week boundary starts a new streak unit; target changes within the same fixed boundary preserve continuity. Daily grace rules continue only in daily periods; weekly flexibility comes from the weekly target, with no additional missed-day allowance. Preserve all earlier daily grace/win tiles. Historical check-in edits recompute derived achievements deterministically.

Consistency assesses elapsed scheduled dates for daily policies and **closed active weeks** for weekly policies. A weekly opportunity is either achieved or not; extra wins never increase its weight. Open weeks have separate live goal progress and do not enter consistency yet. Report periods assign a weekly opportunity to its ending date, so a cross-month/year week is assessed exactly once. Label these mixed denominators as assessed opportunities, not days. Total wins and tile walls always follow their actual dates independently of this assessment rule. Current/best streak labels state weeks versus wins; best streaks count only achievements anchored inside the selected interval and use the currently effective habit kind.

Examples to verify: Sunday/Monday and year boundaries; Saturday short starts; pending/reached/undone open weeks; a missed closed week retaining its wins; capped extra wins; archived and resumed partial weeks; daily→weekly→daily transitions; target edits/repeated edits and restored boundaries; timezone travel; display-week preference changes; v8→v9 preservation/reopen and atomic v4 merge/legacy rejection. Browser and hosted iPhone evidence remain separate from physical accessibility, Android runtime and signed-release gates.
