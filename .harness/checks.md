# Verification gates

Required local aggregate: `npm run verify` (types → lint → format → unit → real SQLite integration → iOS/Android/browser JS exports). CI reproduces it with Node 24 and `npm ci`, then requires mitigation integration regressions, `npm run security:bundle` and `npm run security:policy`. The production iOS JS inventory must exclude both affected tooling packages; missing/malformed inventory or affected modules fail. Raw `npm run security` still fails on high/critical dependency findings. Owner-approved ADR-020 temporarily accepts only two known tooling advisories after exact patched-source/ancestry verification and mitigation regression tests, until 2026-10-22T00:00:00Z. Unknown alerts, scanner errors, missing/tampered patches, critical findings or expiry fail closed; raw report/result remain visible. Never describe skipped gates as passed.

Device acceptance: install native app on a dedicated test device, run `npm run test:e2e`; test the same Maestro flow on iPhone and Android. Review screenshots at narrow widths and enlarged system text; check VoiceOver/TalkBack and reduced motion. Exports are not native build evidence.

Android runtime acceptance (task 028): use a dedicated temporary AVD and synthetic data, never an owner's existing AVD or physical device implicitly. Verify the native APK source against native/dependency inputs and record the served working-tree JS when testing an uncommitted fix. Metro must listen on IPv4 for Android emulator loopback access; startup failures are not acceptance. Android tab accessibility labels omit the iOS `, tab, N of 3` suffix; action selectors accept both exact forms while retaining required destination/persistence assertions. Review the note footer with the real keyboard open: Done typing, Save note and Close day must remain reachable. Do not hide the keyboard in the test to bypass an obscured app action. Retain initial failure hierarchies and final JUnit/screenshots. Test native share/file selection, cancellation and reviewed restore, including preserved local preferences. Record emulator API/size/font scale/locale/reduced-motion readbacks and distinguish simulator evidence from physical TalkBack and signed-candidate checks.

Native tooling, store accounts, licensing and hosted branch protection are outside the secret-free CI gate. Record unavailable checks and next actions in the task/report. Never upload user habit databases.

Browser preview acceptance: npm run preview, open http://localhost:8090, create → complete → reload → verify → undo → reload → verify. Confirm exactly 14 accessible dates per habit and inspect list/form at 390px and 360px. Reopen a new tab to check origin-scoped storage. This does not replace native Maestro.

## Keep the harness current

Every new behavior must update its scoped task, acceptance criteria and required tests/flows, plus backlog and delivery evidence. Record new architecture decisions in ADRs. Keep commands/results and unavailable gates explicit; do not mark native acceptance from a browser screenshot or a successful export. Preserve owner edits to the plan.

Celebration acceptance: successful changed win → brief individual feedback; the last positive planned win today → distinct all-day feedback. Undo, duplicate marks, failed writes and reading/restoring/reloading data must not create a celebration. A day with no positive planned opportunities must never claim an all-day celebration; deliberately recording an eligible past win may receive individual feedback. Verify saved animation disable/re-enable, no replay and OS reduced motion; static win/tolerance/note state and exactly 14 Today dates remain correct.

Native scrolling controls: center off-screen/partially covered targets before tapping so the tab-bar inset cannot cover the hit target. An accessibility tree can still expose an off-screen row; diagnose with captured bounds and screenshots, including enlarged text. First/last items of a full-screen modal may be impossible to center: require full visibility and safe-area evidence instead of repeatedly scrolling past the content end. Note actions use a fixed footer above the keyboard. Keep exact text, selected-state and restart assertions; preserve both new-feature and regression JUnit reports.

System appearance acceptance changes the dedicated simulator OS style, captures readback and asserts the resolved app palette, not only the selected radio. Verify stored Light/Dark overrides after restart and switching back to System. Preserve management fixture data for enlarged text. Habit-name acceptance checks exact draft text before closing the editor and exact saved title afterwards; diagnose malformed input rather than accepting changed names.

Release dependency check: inspect source maps/module inventory for the final signed production candidate. The inspected iOS JS export excludes braces/node-forge; that does not automatically certify a later signed archive. If affected runtime code is shipped or mitigation evidence changes, reassess release readiness rather than relying on the tooling exception.

Language acceptance: keep the English native suite and test Portuguese override → restart → habit/check-in/note → restart → English override without renaming user data. The final iPhone flow changes only the dedicated simulator's global language to pt-BR, captures AppleLanguages readback, starts from no saved override and verifies System resolves Portuguese, then an explicit English override and return to System. Review Portuguese with accessibility-large; Android system-language/foreground changes and physical screen readers need separate evidence. App-provided share titles follow the saved interface language. System-owned picker/share controls are not translated by this preference; actual dialog localization remains a separate device gate. Backup merge must retain all device preferences, including language.

The earlier eight-flow baseline took 32m48s (38656406501); the complete ten-flow language baseline took 41m27s (38785809828). Starter-idea baseline 38800367178 took 42m45s. The additional weekly create/restart/edit/undo flow, enlarged weekly configuration and compact artifact upload need headroom within the 55-minute job cap; element deadlines and all previous cases remain unchanged. This execution capacity does not replace element/assertion deadlines or permit failures; preserve all eleven flows. Diagnose driver screenshot/transport failures from the captured XCTest logs before retrying on a fresh runner.

Settings navigation acceptance must assert the stable settings-theme-(light|dark) screen root after tapping the tab, before scrolling to a preference. Use the existing retryTapIfNoChange first-interaction safeguard; do not interpret a missed navigation tap as a missing/off-screen preference. Keep all exact selected-state/palette/restart assertions. Native phases collect independent evidence even after a feature failure: regressions need the prepared bundle, system/enlarged-text phases need the management fixture, and the final OS-language flow needs the prepared bundle. Any failing step keeps the job failed; skipped dependent checks are never accepted as passed.

New-habit entry must confirm the unique Close habit editor label before typing. The New habit label alone is ambiguous because it also names the Today add button. If the editor is absent, one bounded idempotent reopen is permitted before the required assertion; do not repeat Save or mutate records as recovery. In enlarged text, scroll to required body content before asserting it and retain a separate header capture. Failed feature phases publish a lightweight diagnostic artifact before independent checks, while the job remains failed and the full final artifact is retained. Maestro [selectors](https://docs.maestro.dev/reference/selectors/core-selectors) support text/ID regex; [tapOn](https://docs.maestro.dev/reference/commands-available/tapon) documents the first-interaction retry safeguard.

Weekly goal acceptance: retain all ten existing flows and add weekly-goals.yaml (one-day target → real win → restart → target edit for next boundary → undo/restart). ## Marketing site

For website changes run `python3 scripts/check-website.py` and the required aggregate. Review keyboard navigation, local support/privacy links and 360px/desktop layouts. Store placeholders are status text until real URLs exist. Check the published project subpath as well as local preview; only website/ is uploaded. Native device acceptance is not applicable to this isolated static site.

Bilingual site acceptance (task 027): run `node --test scripts/check-website-language.mjs` as well as the Python artifact check. Check English fallback, Portuguese browser resolution, both manual overrides, Browser language reset, reload/internal navigation, support/privacy and fragment preservation. Inspect all three screenshots at desktop and 360/390px: intrinsic and rendered aspect ratios must match phone viewport captures. No full-scroll mockups, clipping or rotation. Keep both complete static language versions and disclose the local website language preference. Browser storage blocked/unavailable handling has deterministic tests; distinguish that from an actual browser's storage policy.

Android date-grid visual acceptance (task 029): measure the 14 Today cells and representative Insights/detail calendar cells from the native UI hierarchy, in addition to reviewing screenshots. Today/annual cells must be square and equal within one physical pixel of rounding; current-day borders and notes cannot enlarge them. Check empty leading/trailing slots and column alignment. Review week/month/year, 360 dp, enlarged text, long habit names and Portuguese. Calendar inspector tests must scroll back to the header before using its Back control; keep the destination assertion.

Android tab safe-area acceptance (task 039): run the tab-bar flow on a dedicated three-button emulator at normal and enlarged text. Measure actual Today/Insights/Settings accessible bounds against the stable application area and inspect screenshots: each tab target must remain at least 48dp high, and its icon/label must fit above system navigation. Successful taps alone missed a 19.64dp clipped target in the original release candidate. Include the bottom inset in an explicit numeric tab-bar height at every font scale.

Native launch acceptance (task 031): rebuild a standalone binary after icon/splash config changes. Inspect actual launcher mask, native light/dark splash → real loading → usable screen, warm resume, offline first-win/restart and upgrade retention. Check Portuguese/enlarged text/reduced motion, and inject a recoverable initialization failure only in an isolated synthetic database; native splash must release to error, retry must open a fresh usable connection without losing history. Preserve and restore the fixture/version and emulator settings. Expo Go/export/prebuild are not native runtime evidence.
